# Recipient Portability

`{SKILLS_ROOT}` is the installed plugin's skills directory. `{RECIPIENT_RESOURCE}`
means an unavailable source supplied through bindings.json, never an inferred
file or a working command. Run scripts from their owning skill directory.
Ignore private-installation references to a global audit, source archive,
maintenance task or platform connector if absent here. The consumer test command
is `python3 -B -m unittest discover -s tests` from the distribution root.

Skills carry expertise; profiles carry bounded work; the host's native tools
perform execution. Custom-agent TOMLs are supported on compatible Codex hosts;
some app tool schemas expose only generic spawn. In that case pass the role's
work packet to generic spawn, or execute inline. Do not invent custom-agent or
persistent background execution. The journal is local macOS/Linux state.

The recipient's CRM owns identities, suppression and committed outcomes. Bind
its actual parser/schema and owner receipt; the optional relationship validator
only validates its stated contract and cannot authenticate a live database.
No private CRM parser is redistributed. Numeric and prose methods remain usable
without that integration. Research papers require recipient rights and access.

Vendor tools (spreadsheet, presentation, PDF, web and connectors) are external
runtime dependencies, not copied skills. Profiles mention capabilities, not
promised tools. Inspect actual availability and return a precise missing tool
when necessary. No credentials, MCP servers, hooks or paid calls are installed.
