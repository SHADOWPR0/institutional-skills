# Medium Playbooks

## UI / UX / Product

- Start from the product task and user state, not a hero section.
- Reuse existing app components, tokens, typography, spacing, icon library, and state patterns.
- Define the primary workflow, empty/loading/error states, disabled states, confirmation moments, and mobile behavior.
- Prefer recognizable controls: icon buttons for tools, segmented controls for modes, toggles for binary settings, inputs/sliders/steppers for numeric values, menus/tabs for option sets.
- Use visual hierarchy, density, and interaction states to make the workflow faster.
- Validate with screenshots or browser inspection when implementation changes are made.

## Decks / Slides

- Decide whether the deck is for persuasion, education, diligence, fundraising, sales, operating cadence, or board-level decision making.
- Build a slide rhythm: title claim, evidence, visual support, implication.
- Use fewer decorative motifs and stronger hierarchy.
- Charts must have one takeaway, visible units, and honest scale.
- Use speaker notes or appendix for excess explanation instead of crowding slides.
- Keep visual treatment consistent across titles, section dividers, data slides, process slides, and closing asks.

## Documents / Letters / PDFs

- Treat layout as trust architecture: margins, type hierarchy, paragraph length, headings, callouts, signature blocks, and evidence placement.
- Keep prose owner separate from visual owner: use `ethical-supersuader` for language quality and this skill for presentation.
- Use restrained emphasis. If everything is bold, nothing is.
- For formal letters, prioritize credibility, clarity, scannability, and recipient action.
- For PDFs, verify page breaks, table width, footnotes, headers/footers, and print readability.

## Reports / Dashboards / Data Viz

- Start with the decision the report supports.
- Choose visuals by question type: trend, comparison, composition, distribution, correlation, funnel, cohort, table, or exception list.
- Put units, time windows, denominators, and definitions near the chart.
- Avoid chart decoration that makes values harder to compare.
- Use tables for operational review and charts for pattern recognition.
- Make the first view answer "what changed, why it matters, and what to do next."

## Landing Pages / Marketing Surfaces

- Use `growth-operating-system` for offer, audience, CTA, experiment logic, and measurement.
- Use this skill for hierarchy, layout, imagery, proof placement, section rhythm, visual tone, and conversion clarity.
- The first viewport should communicate the literal offer or brand and show a hint of the next section.
- Avoid generic SaaS sections unless they serve the buyer journey.
- Use real product, customer, venue, object, or workflow imagery when inspection matters.

## Social / Content Creative

- Define the feed context: LinkedIn, X, email, newsletter, blog, short video, carousel, ad, or internal update.
- Make the visual support the hook, not repeat it.
- Prioritize crop safety, title readability, contrast, and recognizable brand cues.
- For carousels, each frame needs one idea and a reason to advance.
- For thumbnails, design for small-screen legibility before full-size polish.

## Image / Video Direction

- Use `imagegen` or `sora` for execution.
- This skill owns the brief: subject, purpose, composition, visual register, camera/lens or graphic style, lighting, motion, text handling, aspect ratio, and failure modes.
- Generated media should reveal the actual product, place, object, state, gameplay, person, or concept when inspection matters.
- Avoid purely atmospheric visuals when the user needs concrete evidence or comprehension.
- For edits, preserve the user's source content unless the requested change requires alteration.

## Brand / Design System

- Do not create a brand system unless there is repeated use or a clear need.
- Start with the smallest reusable layer: typography, color roles, spacing, component primitives, imagery rules, chart rules, and icon style.
- Keep brand expression tied to audience and business context.
- Document decisions in the artifact's design source of truth, not as permanent global taste law.
