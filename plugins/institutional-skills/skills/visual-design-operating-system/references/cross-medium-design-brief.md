# Cross-Medium Design Brief

Use this when the user asks for design help but the visual direction is loose.

## Brief Fields

- Artifact: what is being designed or polished?
- Medium: UI, deck, document, letter, report, dashboard, landing page, social/content, image, video, brand system, or critique.
- Audience: who must understand or act on it?
- Job: what decision, belief, action, or memory should the artifact produce?
- Stakes: casual, internal, client-facing, investor-facing, regulated, high-value, or public.
- Source of truth: Figma, existing app, brand file, prior deck, screenshots, website, notes, data, or user taste.
- Tone/register: institutional, editorial, luxury, data-dense, direct-response, founder-led, premium technical, consumer, playful, cinematic, minimal, or other.
- Density: sparse, balanced, dense, or executive-summary.
- Required assets: logos, photos, charts, screenshots, diagrams, icons, generated images, motion, or video.
- Constraints: size, format, device, print, accessibility, brand rules, compliance, deadline, or toolchain.
- Success test: what would make the user say this is clearly better?

## Preference Source Order

1. Explicit user instruction.
2. Existing brand/design system or source artifact.
3. Audience and medium norms.
4. The artifact's functional job.
5. Current design best practices and accessibility constraints.
6. External design references, only after provenance/licensing is clean.

Do not invent a permanent house style when the task only needs a contextual design decision.

## Fast Clarification Rule

If the missing information is low-risk, make a conservative assumption and proceed. Ask the user only when the design could materially misrepresent a brand, client, legal/compliance posture, investment claim, or paid deliverable.
